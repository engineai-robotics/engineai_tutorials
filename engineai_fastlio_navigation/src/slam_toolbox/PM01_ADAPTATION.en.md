# PM01 SLAM backend adaptations

[简体中文](PM01_ADAPTATION.md) | English

Upstream: [SLAM Toolbox 2.6.10](https://github.com/SteveMacenski/slam_toolbox/tree/8293d21fe5c816d0405e0cc1f3eb46c70659c267), fixed at `8293d21fe5c816d0405e0cc1f3eb46c70659c267`. The adapted source is included directly in this repository and maintained in Git. The upstream source layout and licenses are retained.

Local-match validation runs before Karto writes a normal match to the scan cache, running scan list, or graph nodes. It checks the residual against the LIO prediction at the measurement timestamp, valid-range support, response, competing peaks, and accumulated correction during a turn. Neighbor-chain matching and candidate fusion are also checked against the original LIO prediction before constraints are added. Local responses and competing peaks are normalized by the number of finite measurements; original correlation scores, covariance, and global loop-closure thresholds remain unchanged. A rejection preserves the last accepted scan. Recovery requires three consecutive reliable observations with different measurement timestamps. If the normal cache cannot match, the search selects at most 30 accepted references within 4 m of the LIO prediction at that timestamp. History and the graph remain unchanged until validation succeeds. Global loop closure continues through its separate upstream validation path.

The backend publishes internal JSON metadata on `/pm01/slam_match_update` and `/pm01/slam_map_revision`. Source timestamps use integer nanoseconds. Map revision metadata and the occupancy grid are generated under the same backend lock. Public map and pose message types remain unchanged. The integration layer requires backend validation metadata before accepting a SLAM pose. Accepted updates carry an `anchor_id`. After graph optimization, `/pm01/slam_graph_anchors` reliably retains the keyframe pose table for that revision so live evidence can be reprojected by anchor. Normal updates do not resend the full table; the table contains neither point clouds nor scan ranges.

Validation parameters are configured in the existing `config/matching/slam.yaml`, with no additional tutorial steps. Normal tracking and neighbor-chain matches have a translation residual limit of 0.20 m. The main recovery candidate after a mismatch may use 0.40 m, but requires three observations with different measurement timestamps that agree with the pose predicted from the first recovery candidate using LIO increments. The graph is updated only after the third passes. The single-frame yaw residual remains limited to approximately 2°. The main recovery candidate allows approximately 5° of accumulated correction; normal tracking and neighbor-chain matches remain limited to approximately 2°. A new accumulated-correction segment starts only when the validated third frame is committed. Rejections and the first two recovery frames leave the reference unchanged. Support and ambiguity limits remain unchanged.

The package's `test/` directory covers local validation, sparse-scan scoring, and graph-write boundaries during recovery. Run it with `colcon test --packages-select slam_toolbox`.
